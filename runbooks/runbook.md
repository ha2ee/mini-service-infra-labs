# Runbook

## 목적
이 문서는 mini-service-infra-lab 앱에 문제가 생겼을 때 기본적으로 확인할 절차를 정리한다.

## 대상 서비스
- App: FastAPI 기반 실습용 HTTP 서비스
- 기본 주소: http://127.0.0.1:8000

## 주요 엔드포인트
- `/health`: 프로세스 생존 확인
- `/ready`: 준비 상태 확인
- `/slow`: 지연 응답 테스트
- `/error`: 의도적인 500 에러 테스트

## 기본 점검 순서

### 1. 앱이 응답하는지 확인
```bash
curl http://127.0.0.1:8000/health
```
기대 결과
- `200 OK`

### 2. 준비 상태 확인
```bash
curl http://127.0.0.1:8000/ready
```
기대 결과:
- `200 OK` 또는 현재 설정에 따라 `503 Service Unavailable`

확인 포인트:
- `LAB_ENV` 환경변수 미설정 시 `503`이 발생할 수 있다.

### 3. 헬스체크 스크립트 실행
```bash
./scripts/health-check.sh
```
확인 포인트:
- `/health`가 `200` 인지
- `/ready`가 200 또는 `503`인지

### 4. 앱 프로세스 확인
```bash
ps -ef | grep uvicorn
```
확인 포인트:
- uvicorn 프로세스가 실행 중인지

### 5. 포트 리슨 상태 확인
```bash
ss -lntp | grep 8000
```
확인 포인트:
- 8000 포트를 앱이 리슨 중인지

### 6. 앱 로그 확인
확인 방법:
- uvicorn을 실행한 터미널에서 요청 로그와 에러 로그를 확인한다.

확인 포인트:
- `/health`, `/ready`, `/error` 요청이 실제로 들어왔는지
- 500 응답이 의도된 `/error` 요청인지

## 자주 볼 수 있는 증상과 해석

### `/health`가 실패하는 경우
가능한 원인:
- 앱이 실행되지 않음
- 잘못된 포트로 실행됨
- 프로세스가 죽음

### `/ready`가 503인 경우
가능한 원인
- `LAB_ENV` 환경 변수가 설정되지 않음
- readiness 조건을 만족하지 못함

### `/error`가 500인 경우
설명:
- 의도적으로 만든 장애 재현용 엔드포인트
- 현재는 정상적인 실습 동작

### 복구 초안
- 앱 재실행
- 환경변수 확인
- 포트 확인
- 로그 확인
